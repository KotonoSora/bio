# Account and Access - Acceptance Criteria (feature 01)

Phase 1 BA · BDD checks gating the release of `docs/02-architecture-techlead/01-account-and-access/`. Rules cited as `BR-nn` from `docs/01-requirements-ba/01-account-and-access/02-user-stories-and-business-rules.md`.

| AC ID | Scenario | Given | When | Then |
|---|---|---|---|---|
| AC-01 | Password-dead drill | Any email/password, signup, or reset attempt | Endpoints, DB, and UI are probed | Endpoints return `404 auth_disabled`, no verifier is populated, no password/reset surface exists anywhere (BR-01) |
| AC-02 | Login happy path | Each provider x new vs returning, including relay and email-denied cases | The flow completes | New users land on the username chooser with correct cookie flags; returning users resolve to the same account; relay/denied-email are prompted, never blocked (BR-02, BR-03, BR-14) |
| AC-03 | Stable identity and collision | A returning user changed IdP email; another user's email collides | Login completes | Same account via `sub`; verified email syncs only when collision-free; collision shows the notice with no merge and no cross-user exposure (BR-02, BR-03) |
| AC-04 | Callback security drill | Replayed code/`state`, mismatched PKCE, expired `state`, cross-account `state`, off-allowlist `callbackURL` | Each callback is processed | All fail closed with generic `auth_failed`; no session is issued (BR-04) |
| AC-05 | Linking drill | An authenticated account with one and then two linked providers | Link and unlink are attempted with stale and fresh step-up | Stale step-up refused; last-link unlink refused `409`; unlink with two providers succeeds; both logins resolve to one account (BR-05, BR-07) |
| AC-06 | Session lifecycle drill | A session active and idle past bounds | Idle timeout, absolute lifetime, revoke, revoke-all-others, and logout are exercised | Bounds enforced; revocation effective within 60 s; current session survives "others"; logout kills the session everywhere (BR-06) |
| AC-07 | Step-up drill | Each of the six sensitive actions, with and without fresh re-auth | Action is attempted | Stale (>10 min) and absent re-auth -> `403 step_up_required`, nothing applied; after re-auth the action completes (BR-07) |
| AC-08 | IDOR/RLS drill | A userA session targeting userB identity, session, or link rows | Reads, writes, revokes are attempted | `403` mutations, `404` private reads; app-role RLS returns zero foreign rows; `user_id` never accepted from clients (BR-08) |
| AC-09 | Entitlement propagation | A plan change committed at the ledger; then a snapshot outage | A pro-only capability is used right after each event | Change honored within `≤ 30 s`; outage clamps to free with the miss counter; re-upgrade restores with no data loss (BR-09) |
| AC-10 | Audit completeness | Link, unlink, step-up, recovery, and login events occur | The audit log is read | Each event has actor, subject where applicable, action, target, timestamp; app role cannot UPDATE/DELETE rows (BR-11) |
| AC-11 | Abuse and enumeration drill | Bursts on `/api/auth/*`; existing vs non-existing account probes | Throttles and analysis run | Bursts throttled with `429 throttled`; no reliable existing-vs-new oracle in wording or timing class (BR-13) |
| AC-12 | Recovery drill | A locked-out user with documented evidence; then an expired token | Support triggers the invitation; the token is used and replayed | Invitation single-use, 15 min TTL; no credential ever visible or set; replay fails; audit row cites the evidence (BR-12) |
| AC-13 | First-login handoff | A fresh account with no profile; then a transient profile-service failure | Login completes | Chooser route shown; on lookup failure the default `/app` recovers without error loops; profile creation stays race-safe under feature 06 rules (BR-14) |
| AC-14 | Edge degrade drill | Edge session cache cleared; then account-service made unreachable | Session-validated requests are sent | Cache miss rebuilds via introspect and the session continues; both-unreachable fails closed with `503` for owner routes; no fail-open path exists (BR-08) |
| AC-15 | Prefill/XSS drill | IdP-supplied name and avatar with markup, script, oversized and fake image payloads | Login surfaces render and avatar prefill runs | Markup stripped, CSP holds; prefill follows feature 09's 2 MB / magic-byte / random-key rules; IdP URLs never hotlinked (BR-15) |
